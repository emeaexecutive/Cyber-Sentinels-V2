## Root cause and recovery

The previous consent manager awaited synchronous Supabase, Trust Event, and Evidence persistence before closing the modal. Production receipt persistence returned HTTP 500, so the visitor remained trapped behind `Consent operation failed safely.`

The recovery stores an anonymous necessary consent receipt in browser storage first, closes immediately, and synchronizes the existing consent ledger through `POST /api/consent/cookies` with a stable idempotency key. If server persistence fails, the receipt remains `pending_sync`, a non-blocking retry is offered, and every optional tracker stays denied.
