3. The current tenant/workflow/purpose-specific Living Trust Profile is derived.
4. Test Mode provider evidence and a recorded workload credential are checked.
5. The action moves from preparation to approval, runtime risk changes and transaction value crosses the policy threshold.
6. Continuous authorization records each trigger and evaluates authority again.
7. The result becomes `require_approval`; a governed pause is recorded without claiming external execution.
8. The existing enforcement path requires an execution receipt.
9. Replay retains the action, changes, decision and control reference.
10. Trust Memory records the explained `challenged` transition.
11. Trust DNA updates its dimensions, risks, evidence completeness and next action.
12. The accountable owner can revoke or restore authority through governance, producing new Replay and Trust Memory evidence.
