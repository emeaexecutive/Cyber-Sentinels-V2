Design precedes feature code. Sources inspected: live Staging information_schema, migrations `202607200001`, `202607210001`, `202608010001`, `202608060002`, `202608090002`, `20260907120000`, public API runtime and serious-incident repository/service.

| Concept | Existing representation | V2 decision |
| --- | --- | --- |
| Authorization | canonical_trust_transactions | Reuse; no decision or purpose rewrite |
| Declared purpose | action_purpose, authority_reference, authority_lineage_references, policy fields and decision snapshot | Reuse at decision time |
| Observation and provider context | evidence_objects.normalized_facts, provider_key/source fields, subject and digest | Reuse independently sourced evidence; typed V2 projection |
| Native execution | native_runtime_execution_observations, native_destination_observations | Read existing facts where available; native request FKs make these unsuitable for generic external assertions |
| Outcomes | public_api_outcome_submissions, external_action_outcomes, native_enforcement_outcomes; evidence_objects for additional attributed operational facts | Reuse; retain provider/runtime/destination distinctions |
| Incident root | incident_regulatory_assessments | Reuse with explicit canonical operational mode; make jurisdiction and model/system optional only in that mode |
| Chronology, intervention, remediation evidence | incident_chronology_events | Reuse append-only chronology; provider reports do not become confirmed remediation |
| Governed corrective workflow | incident_corrective_actions | Reuse existing approvals; generic reports do not bypass it |
| Export | incident_submission_packages | Reuse immutable versioned packages in internal_draft; canonical completeness does not imply regulator approval |

| Connected graph | evidence_graph_nodes/edges | Reuse tenant-scoped nodes and relationships |
| Memory | trust_memory_index | Append references and later interpretations, never overwrite old facts |

## Minimum additive representation

Implemented single new relation: `incident_evidence_links`. Existing chronology has a free-text evidence_reference and no canonical transaction FK; graph edges alone do not enforce a chronology/transaction/evidence tenant tuple. The link therefore binds enterprise, incident, chronology event, canonical transaction and optional evidence object with five foreign keys. It carries bounded context/interpretation details, server digest and receipt time; provenance comes from the referenced evidence. It is not a second evidence ledger.

No execution_observations, trust_outcomes, trust_incidents, trust_evaluations, regulatory_evidence_exports, trust_context_subjects, provider_activity_context, purpose_observations or cross_context_links tables are justified. Existing identity and graph relations carry continuity.

## Migration contract

One forward migration, generated by CLI, smallest additive change. Historical files and migration ledger hashes remain unchanged. No reset. Local qualification precedes Staging application. Compare the full pre/post migration ledger; apply only the exact reviewed migration to the confirmed Staging ref.

Applied Staging version: `20260909163513_operational_incident_evidence_foundation.sql`. The initial CLI-generated draft was renamed to the version assigned by Supabase on application; its SQL was unchanged. Staging grew from 130 to 131 migrations, with all 130 existing names and statement hashes unchanged. Local PGlite qualification uses captured live column definitions plus a minimal dependency fixture; it is targeted migration testing, not a full V1 schema replay. Actual Staging tests separately exercise the existing authenticated workspace-membership function, grants, RLS and live constraints.

Ownership is the existing trust workspace. Composite keys prevent cross-tenant incident/event/transaction/evidence attachment. Index enterprise+incident+received time and enterprise+transaction. Enable RLS, revoke defaults, grant authenticated SELECT with user_can_access_trust_workspace; no direct client writes. An atomic service-only persistence RPC must enforce tenant/client/transaction/incident consistency and use a fixed search_path. Revoke PUBLIC/anon/authenticated EXECUTE. Authenticated-role SQL tests must prove isolation; service-role success is insufficient.

All V2 history is append-only. Restrictive FKs preserve evidence references; retention and legal-hold fields on evidence remain authoritative. No automatic deletion duration is promised. Expired or unavailable evidence yields an explicit gap. Exports contain references and bounded facts, not raw payloads or copied evidence graphs. Forward-fix strategy: stop V2 writers and add a corrective migration; keep V1 running independently. No destructive down migration.
