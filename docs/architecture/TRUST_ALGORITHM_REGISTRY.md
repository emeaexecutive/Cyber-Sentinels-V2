# Trust Algorithm Registry

This is the canonical inventory of deterministic trust algorithms in the product. “Fail closed” means the algorithm returns `DENY`, `REVIEW`, an unknown state, or no autonomous execution; it never manufactures a positive result. All algorithms are tenant-scoped at their persistence or retrieval boundary.

| ID | Algorithm / version | Inputs | Outputs | Principal reason codes | Deterministic rules | Fail-closed behaviour | Evidence dependencies | Tests |
|---|---|---|---|---|---|---|---|---|

| B | Identity correlation / 1.0 | Normalized provider subject, session and signal attributes | Tenant-scoped correlated identity evidence | `IDENTITY_UNRESOLVED`, `IDENTITY_CONFLICT`, `PROVIDER_EVIDENCE_STALE` | Normalize before correlation; retain provider and source identifiers | Ambiguous or missing correlation remains unresolved and cannot independently establish trust | Provider adapter output, identity evidence, session | `identity-signals.test.mjs`, `identity-signals-integration.test.mjs` |

| M | Trust Confidence / 1.0 | Completeness, freshness, independence, agreement, authority, outcome, continuity, contradictions | `HIGH`, `MODERATE`, `LOW` or `INSUFFICIENT` with factors | `INSUFFICIENT_EVIDENCE`, `LOW_SOURCE_INDEPENDENCE`, `UNRESOLVED_CONTRADICTIONS` | Weighted, bounded factors with explicit penalties; it measures conclusion confidence, not trustworthiness | Missing evidence yields `INSUFFICIENT`; confidence never authorizes execution | Evidence and authority references, outcome and continuity observations | `continuous-operational-trust-intelligence.test.mjs`, `product-truth-runtime.test.mjs` |

Grounded AI governance is deliberately outside the decision registry: it is advisory only. When configured, `lib/ai/governanceAssistant.ts` uses server-side OpenAI structured output, an exact evidence allowlist and post-response citation validation. Unsupported model output is rejected and replaced by an explicitly labelled deterministic result. It cannot override algorithm I.

Persistence and retrieval are implemented through the repositories/API routes named in `config/product-capabilities.json`; the registry CI verifies every referenced source, API, UI, test and qualification-evidence file exists.
