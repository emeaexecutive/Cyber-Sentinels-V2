# Architecture Decision Records

ADRs capture durable architecture decisions and their trade-offs.

## Status values

- `Proposed`: under review and not yet authoritative.
- `Accepted`: authoritative for new and materially changed work.
- `Deprecated`: retained for history but no longer recommended.
- `Superseded by ADR-NNN`: replaced by a later decision.

## Rules

1. Use the next sequential number and a lowercase kebab-case filename.
2. Include Status, Context, Decision, Alternatives, Consequences, Security impact and Future work.
3. Do not rewrite the central decision of an accepted ADR; supersede it.
4. Link implementation evidence, but do not call proposed or source-only behavior deployed.
5. Record migrations and compatibility consequences explicitly.
