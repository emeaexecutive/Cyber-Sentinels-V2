# Spanish public website candidate

The 42 canonical public pages have English and Spanish owners. Eleven routes translate the actual publication-under-review notice, never the unpublished draft legal/policy content. Account tools, the guided demo and downloadable documents can remain English; the language selector and relevant download/control labels explain that scope. No additional language is advertised as available.

The remaining public prose uses 1,098 reviewed catalogue messages. Existing English page implementations and six supporting presentation/data modules generate the Spanish counterparts; callbacks, code examples, machine identifiers, API schemas, scope strings and style tokens remain unchanged. The OpenAPI display projection translates all 26 operation summaries/descriptions while a regression compares every other contract field with the canonical object. It does not change an API route or the raw JSON contract.

Regeneration: inspect English changes, update the catalogue, reconcile the ID snapshot and translation batches, then run `node tools/i18n/generate-spanish-public.mjs`. `--check` rejects generated-source drift. Never automatically approve a new ID snapshot or shift positional translations after adding a message: review the English/Spanish correspondence first. Existing source ID order is pinned separately from the inventory, so re-running the inventory cannot silently approve mismatched translations.

Real locale routes and trusted middleware headers preserve HTML language and metadata. Language changes use a document navigation, retaining query/fragment values. Every English owner advertises the real Spanish equivalent; sitemap and hreflang cover both owners. Untranslated account/demo paths retain the explicit English fallback.

Long technical sections use native disclosures in both languages. Their content stays in rendered HTML and hash navigation opens the selected section. This reduces the initial reading load without removing arguments, sources, examples or controls. Historical whitepaper capability statements are labelled as historical/source evidence, not fresh Production qualification. The existing PDF remains the English edition and is labelled accordingly in Spanish.

Local proof commands: `npm run test:search`, `npm run test:public-surface`, `npm run test:turnstile`, `npm test`, `npm run build`; run the built site on loopback port 4340 and `npm run test:spanish-browser`. The public UI browser proof deliberately runs without database bindings and refuses a hosted origin. It checks rendering, metadata, responsive layout, navigation, anchors and invalid-form non-submission; it cannot qualify Auth, consent persistence, positive Turnstile or provider execution.

Preview binding changes are prepared in PREVIEW-STAGING-BINDINGS.json, not applied. Private Auth/backup/Turnstile dashboard inspection is blocked because the browser access host and native Computer Use connection are unavailable. Staging is ACTIVE_HEALTHY; its new approval/dispatch v2 RPCs are absent. Website and execution qualification have separate migration/write approval gates. Production has not changed, and this candidate has no Production promotion approval.
