# Release 1 reviewer guide

Use `/admin/reviews`. Confirm case scope, provenance, licence, limitations and safe evidence references. Compare expected and actual behavior, then record a ground-truth label, confidence, rationale, uncertainty and disagreement. Use `reviewed`, `disputed`, `excluded` or `approved` deliberately.

Fixtures are synthetic product-behavior tests, not facts about people or provider accuracy. Never infer authenticity from provenance alone. Dual-review approval requires two distinct reviewers. History is append-only; corrections are new review events, not edits to prior events.
