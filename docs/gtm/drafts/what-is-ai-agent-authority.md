# What Is AI Agent Authority?

**Question:** What is AI agent authority?

AI agent authority is the permission an organisation has deliberately delegated
to an agent for a defined action, purpose and scope. It answers a different
question from identity. Identity asks *who or what is acting?* Authority asks
*what may it do, for whom, and under which current rules?*

That distinction matters when an agent can use tools, access data or start work
across multiple systems. A verified identity can help identify the actor, but it
does not automatically authorize every action available to that actor. A
previous approval is not a permanent permission slip if the task, target, policy
or risk context has changed.

## What should a permission describe?

An organisation should be able to explain the action being requested, its
purpose, the intended target, the scope of access, the responsible owner and
whether human review is required. Those boundaries should come from the
organisation's policy and delegation—not from an agent's own claim about what
it is allowed to do.

For each consequential request, teams can ask:

- Is this the expected agent and organisational context?
- Is this action allowed for this purpose and target?
- Does the delegation still apply under current policy?
- Should the request proceed, wait for review or be denied?
- What evidence will help explain the decision later?

An ALLOW, REVIEW or DENY decision is useful only when its meaning is clear at
the boundary that controls the action. A decision record is not, by itself,
proof that another system carried out an action.

## Authority is accountable

Delegation should have an accountable owner, a bounded purpose and a way to
change or withdraw permission. Organisations also need a human response path
when policy is unclear or the consequences are significant. These practices
help keep responsibility with the organisation even when software performs
parts of a workflow.
