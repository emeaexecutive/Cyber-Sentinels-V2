# Epic 28 Platform Reconciliation

Epic 28 reconciles the Enterprise Trust Fabric without adding a second Identity, Authority, Evidence Graph, Trust DNA, Continuous Trust, Replay, Trust Memory, Scope Continuity or incident engine.

## Delivered boundaries

- One canonical Trust Object and five-state trust model.
- One evidence taxonomy: asserted, configured, observed, independently attested, cryptographically attested and derived.
- One deterministic composition control plane and decision envelope.
- One Trust Contract foundation and one Enterprise Trust Timeline projection.
- One provider runtime-state contract and one synthetic evidence adapter.
- One six-state Replay availability contract.
- One canonical route/navigation and positioning contract.
- All 13 legacy source contracts mapped to executable replacement coverage; the 58-test legacy sweep remains in default CI.
- Epic 26/27 cross-reference, snapshot, chronology, containment, review, correction, Replay and Trust Memory reconciliation.
- An exact, hash-pinned, review-only staging package; migrations are referenced, never copied.

## Cross-Epic scenario

An AI agent has verified identity and simulation-only authority. Its declaration expects no internet or production access. Independent runtime evidence observes both. Scope Continuity records critical contradictions and returns the adverse scope/trust result. Epic 27 opens an incident, separates occurrence/detection/awareness, preserves containment request versus acknowledgement versus confirmation, performs operational screening, requires specialist review, snapshots exact source IDs/versions/digests, records a reviewer decision and corrective action, forms an internal draft package, and emits Replay/Trust Memory projections.

The Fabric then creates a digest-bound Trust Object, a canonical decision envelope, a unified attributed timeline and an active Trust Contract evaluation. The strongest adverse state is preserved. No legal reporting conclusion or external submission is created.

## Release preparation

`supabase/release/epic-26-27/` contains the exact manifest, migration order, prerequisites, preflight, post-apply, RLS, integrity, inventory, rollback boundary, forward plan and SHA-256 inventory required for isolated review. The authoritative migrations remain under `supabase/migrations` and have not been applied remotely.

## Data minimization and legal boundary

Fabric objects contain references and summaries, not evidence bodies or restricted provider payloads. APIs do not log evidence bodies or expose service credentials. LLM output is never final trust, authority, permit, deny, revoke, containment confirmation or legal authority. Operational regulatory screening merely routes specialist review.

## Known limitation

A historical `provider_health_snapshots` collision occurs before Epic 26 in a clean Supabase preview. Historical migrations are immutable; resolution requires the documented forward-only repair and a new clean preview. This prevents staging execution approval but does not authorize production mutation.
