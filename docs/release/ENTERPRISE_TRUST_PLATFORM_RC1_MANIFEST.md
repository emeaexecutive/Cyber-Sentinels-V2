## RC1 scope

- the three existing Production Dependency Baseline commits;
- Enterprise Trust Platform coordination UI and documentation from Epic 36;
- canonical, derived Trust Decision Intelligence from Epic 38;
- provider-neutral and non-authoritative AI-assistance contracts;
- focused platform and decision-intelligence tests;
- RC1 architecture, truth, inventory, PR and rollback evidence.

## Excluded scope

- Epic 39 Trust Simulation and Resilience work;
- open Trust Learning PR #26 and its development migration;
- new database tables, migrations, APIs, live providers, model training, or production deployment;
- a new Trust Journey store—the current Journey remains a UI projection;
- live staging, enterprise-scale, legal-sufficiency, and Production proof not captured on the final RC1 head.

## Architecture included

RC1 consumes the frozen Enterprise Trust Fabric registry: Trust Objects, Trust Contracts, Trust State, decision envelopes/history, Authority Lineage, Evidence Graph, Replay, Trust Memory, provider evidence, policy versions, incident/corrective-action evidence, and Trust Journey projections. Decision Intelligence adds a content-addressed explanation envelope only; it owns no mutable ledger.

## Dependency baseline

The baseline commits align React/React DOM, React types, Stripe/API version, PostCSS/Autoprefixer, Node/npm declarations, immutable GitHub Actions, SBOM/licence evidence, dependency policy, and rollback evidence. `package-lock.json` was generated by npm and is not manually edited by RC1 consolidation.

## Database and APIs

RC1 consolidation adds no migration and no API route. Existing canonical persistence and API security remain governed by the Epic 29 frozen registry and its tests. Because no migration changes are included, a Supabase Preview reconstruction is not triggered by this delta.

## UI routes

- `/enterprise` links to the new coordination projection.
- `/enterprise/trust-platform` is a public, controlled, synthetic coordination view.
- `/trust-center` is the native destination for the coordination view's Trust Centre link.

The view must not be interpreted as live customer evidence or a separate dashboard source of truth.

## Tests and release gates

Focused gates include dependency baseline, React compatibility, Enterprise platform, Trust Decision Intelligence, canonical architecture, Trust Fabric, Replay, Authority Lineage, Trust Memory, Evidence Graph, migration namespace, release manager, observability, security tooling, public positioning, Turnstile/request-demo, and enterprise experience. Final qualification requires clean install, valid dependency tree, lint, typecheck, full tests, production build, non-mutating audit, SBOM regeneration, Gitleaks, and two reproducible install/build cycles.

All local gates passed twice. Exact focused counts, build signals, artifact hashes and environment-bound limitations are recorded in `docs/release/RC1_LOCAL_VALIDATION.md`.

## Staging and Production status

The prior dependency-only head had a successful protected Vercel Preview. That proof does not qualify the later RC1 head. The final RC1 head requires a new Vercel Preview and hosted-check review. Local Supabase and Turnstile public configuration is intentionally absent, so authenticated Trust Centre and live Turnstile smoke checks remain Preview-bound. Production and Production Supabase remain untouched.

## Known limitations

- Trust Journey is a derived UI projection, not a persisted canonical history.
- Decision Intelligence is contract-tested and synthetic; no dedicated persistence/API integration is added in RC1.
- Replay is operationally useful but complete bit-for-bit historical re-execution remains limited where historical versions were not retained.
- No external foundation model, provider, live staging tenant, or enterprise-scale benchmark is claimed.
- Legal sufficiency and financial impact are not inferred.

## Rollback boundary

Revert RC1 consolidation commits in reverse order, then use `docs/release/DEPENDENCY_BASELINE_ROLLBACK_PLAN.md` for the three dependency commits. No data rollback or migration reversal is required for the RC1 consolidation delta. Any rollback remains owner-authorized and must be rebuilt and revalidated before deployment.
