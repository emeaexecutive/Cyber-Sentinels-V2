# Model execution budget and qualification boundary

Implemented in `lib/soc/model-budget.ts`, consumed before inference by `lib/soc/workflow.ts` and enabled in `lib/swarm/operations.ts` only with a trusted server-supplied policy matching the explicit OpenAI model. CHIRIVETA remains deterministic and never invokes this model.

The immutable policy requires an approved **test or staging tenant**, provider/model, shared tenant budget scope/version, positive call limits per window and cumulatively, at most three attempts per investigation, bounded outstanding calls, local duration≤30seconds, input≤32768bytes, fixed adapter output1800tokens, and monetary limits in integer USD micro-units. The workflow applies its own15second model ceiling as an additional restriction. The call adapter also enforces structured output/citations and bounded provider output. Limits are not accepted from evidence, model text, browser JSON or agent fields.

Before the callback executes, an existing persistent SwarmStore transaction appends `SOC_MODEL_BUDGET_RESERVED` and commits its worst-case approved allocation. Invocation replay, investigation retry, call count, outstanding concurrency and spend exhaustion append verifiable denial receipts. The CAS store arbitrates concurrent instances. The existing atomic per-alert investigation claim additionally prevents duplicate or concurrent investigation commands from issuing another callback. There are no automatic model retries.

Both provider response and failure/timeout append `SOC_MODEL_BUDGET_UNKNOWN`. A response's token counters and estimated cost are not independently observed billing. **Money and the outstanding-call slot remain reserved**, including across restart and window rollover. A crashed reservation is conservative: expiry does not refund it. Duration bounds stop local waiting and signal abort; they do not promise cancellation of a provider that already accepted a request.

Only a separately injected `verifyBilling` implementation may authenticate independent invoice evidence plus operator authorization. Reconciliation binds tenant, reservation digest, provider/model, invoice line and evidence reference; duplicate invoices and cross-tenant reuse are rejected. An invoice above the approved reservation is rejected as accounting drift and leaves funds held. No public reconciliation command or unverifiable refund path was added.

This enforces **local admission allocations under an approved worst-case charge**. It cannot create a contractual vendor billing cap. Before real inference, the operator must justify `reserveMicrosPerCall` against the selected model/provider's approved pricing/request ceiling and configure the independent billing verifier. No real invoice, provider cancellation, live token spend or operational price schedule has been qualified.
