# Executive Experience Guidelines

## Above the fold

Every major buyer page starts with an Executive Summary containing no more than four bullets, one primary CTA and one secondary CTA. Avoid long paragraphs, equal-weight action clusters and implementation inventories before the user understands the decision.

## Decision dashboard contract

Every primary dashboard presents six fields before detailed records:

- Current posture
- Current risks
- Recommended action
- Evidence available
- Confidence
- Responsible owner

The recommended action must be operationally specific. Confidence must describe the evidence boundary and must not imply certainty.

## Trust Memory\u2122

Use a chronological timeline with the states Trust gained, Trust lost, Trust restored, Trust decayed, Trust challenged and Trust confirmed. Show explanation, evidence availability and review context. Do not present raw database rows as the primary experience.

## Evidence Graph

Prioritize People, AI Agents, Machine Identities, Workflows, Evidence, Governance and Trust Memory\u2122. Default to a bounded set of the most relevant nodes and relationships. Describe relationships in plain language; retain technical graph fields only in APIs and documentation.

## ML labels

Every ML-related status uses one of these evidence classes:

- Measured
- Estimated
- Awaiting validation
- Provider supplied
- Human reviewed

Do not collapse heuristic logic, provider inference, reviewed outcomes and validated model metrics into one capability claim.
